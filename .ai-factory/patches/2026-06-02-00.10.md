# Simplified T-Bank config to connection_keys-only

**Date:** 2026-06-02 00:10
**Files:** laravel_app/config/broker-systems/tbank.php, laravel_app/config/broker-providers.php, laravel_app/app/Services/BrokerGateway/Providers/TBank/TBankProvider.php, laravel_app/tests/Feature/Config/BrokerSystemsConfigTest.php, laravel_app/tests/Feature/Config/BrokerProvidersConfigTest.php, laravel_app/tests/Unit/BrokerGateway/Factory/BrokerGatewayProviderFactoryTest.php, laravel_app/tests/Feature/Broker/SyncTBankAccountActionTest.php
**Severity:** medium

## Problem

T-Bank config became overly complex and duplicated connection settings across
`environments` and `connection_keys`, with verbose key names and extra fields.
This increased maintenance cost and made simple provider setup harder to reason about.

## Root Cause

The configuration evolved incrementally with backward-compatibility assumptions,
so old and new models were kept in parallel. That produced duplicated sources of
truth (`environments` and `connection_keys`) and drift-prone fields (`label`,
`environment`, `app_name`) inside connection keys.

## Solution

Reworked the config model to use `connection_keys` as the single source of
connection parameters:

- Removed `environments` from `tbank.php`
- Reduced keys to `prod`/`sandbox`
- Kept minimal key schema: `provider`, `base_url`, `timeout`
- Derived `default_connection_key` and `default_environment` from `APP_ENV`
- Updated provider aggregation to consume connection keys directly
- Updated TBank provider runtime lookup to read `connection_keys` instead of
  `environments`, with `app_name` fallback to `investman`
- Removed provider-specific env knobs from `.env.example` (already done earlier)
- Updated feature/unit tests to validate the new contract
- Fixed `SyncTBankAccountActionTest` setup by creating brokers without observer side-effects

## Prevention

- Keep one source of truth for runtime connection params per provider
- Avoid embedding display metadata in low-level infra keys
- When changing model conventions, update consumer tests first
- In observer-heavy models, tests should use `withoutEvents` when setup requires
  explicit field control (e.g., forced `user_id`)
