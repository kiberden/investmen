# Prevent token/expire_at writes to brokers table

**Date:** 2026-06-08 23:05
**Files:** laravel_app/app/Observers/BrokerObserver.php, laravel_app/tests/Feature/Broker/BrokerCredentialSyncFromFormFieldsTest.php
**Severity:** high

## Problem

Saving a broker from MoonShine failed with PostgreSQL error:
`SQLSTATE[42703]: Undefined column: 7 ERROR: column "token" of relation "brokers" does not exist`.

The insert query for `brokers` unexpectedly included virtual form fields
`token` and `expire_at`, which should only be persisted to
`broker_credentials`.

## Root Cause

`BrokerFormPage` exposes `token` and `expire_at` fields for credential input.
During persistence, these transient form attributes remained attached to the
`Broker` model instance and reached Eloquent SQL generation before observer
sync logic ran. As a result, ORM attempted to insert non-existent columns into
`brokers`.

## Solution

- Added sanitization in `BrokerObserver` (`creating` + `saving`) to strip
  transient fields `token` and `expire_at` from the `Broker` model before SQL
  persistence.
- Added `[FIX]` debug logging when transient fields are stripped to keep
  runtime diagnostics traceable.
- Kept credential sync flow intact: `SyncBrokerCredentialAction` still reads
  `token/expire_at` from request and writes into `broker_credentials`.
- Added regression feature tests to verify:
  - broker create/update no longer attempts to write virtual columns,
  - credentials are still synchronized correctly,
  - empty token does not trigger SQL column errors.

## Prevention

- Treat UI-only form fields as transient and sanitize them before model save
  when they do not map to database columns.
- For observer-based sync flows, ensure source-of-truth payload is request data
  rather than mutable model attributes.
- Add regression tests for create/update paths whenever form fields are added
  but persisted into related tables.
