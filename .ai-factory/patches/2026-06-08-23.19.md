# Harden transient broker form field filtering

**Date:** 2026-06-08 23:19
**Files:** laravel_app/app/Observers/BrokerObserver.php, laravel_app/app/Models/Broker.php
**Severity:** high

## Problem

After the first fix, production flow still failed intermittently with:
`SQLSTATE[42703]: Undefined column: column "expire_at" of relation "brokers" does not exist`.

`token` no longer leaked into the `brokers` insert, but `expire_at` still appeared
in SQL for broker persistence under some UI submission paths.

## Root Cause

The observer sanitization removed transient fields only when `getAttribute($field) !== null`.
In certain model hydration paths, relying on attribute value checks was not robust enough.
Additionally, there was no model-level guard to block accidental assignment of form-only
fields (`token`, `expire_at`) into `Broker` attributes.

## Solution

- Hardened observer sanitization to strip transient fields based on attribute-key presence
  (`array_key_exists`) instead of value checks.
- Added model-level transient-field guards in `Broker`:
  - `setTokenAttribute()` now ignores assignment and logs `[FIX]`.
  - `setExpireAtAttribute()` now ignores assignment and logs `[FIX]`.
- Kept credential synchronization unchanged: `SyncBrokerCredentialAction` continues reading
  from request payload and persists into `broker_credentials`.

## Prevention

- For form fields that target related tables, enforce protection at two layers:
  1) observer sanitization before persistence,
  2) model-level attribute guards.
- Prefer key-presence checks over value-based checks when stripping transient attributes.
- Add regression tests that mimic real UI payloads where virtual fields may be present.
